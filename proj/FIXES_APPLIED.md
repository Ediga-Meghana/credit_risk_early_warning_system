# Fixes applied to the existing Risk Platform

## 1. `frontend/src/pages/Assess.tsx`
- The single-company assessment screen now uses Yahoo Finance search only.
- Removed the old company dropdown, guided manual financial-entry mode, and advanced model-ratio mode from the single-company assessment page.
- Kept the separate Batch Prediction page and its company selector/CSV upload.
- Added clearer loading, empty-result, search-error, statement-error, coverage, and insufficient-data states.

## 2. `backend/app/main.py`
- The assistant now automatically attaches the latest saved assessment when a message does not include an assessment ID.
- Validates empty/oversized chat messages.
- Returns assistant mode, notice, and the assessment ID used for context.

## 3. `backend/app/assistant.py`
- Added clearer built-in answers for risk score, SHAP, XGBoost, SMOTE, liquidity, leverage, bankruptcy screening, and Yahoo Finance data coverage.
- Added explicit mode reporting for real Anthropic API responses versus built-in fallback answers.
- API failures no longer fail silently: the frontend can show a notice that the built-in answer was used.
- Uses `claude-haiku-4-5-20251001` when an Anthropic provider is configured but no model ID is supplied.

## 4. `frontend/src/components/Layout.tsx`
- Shows whether a reply came from live AI or the built-in fallback.
- Shows the assistant's setup/fallback notice.
- Clarifies that the latest saved assessment is used when no specific assessment page is open.

## 5. `backend/.env.example` and `README.md`
- Documents the optional Anthropic API setup and notes that a Claude website subscription is not the same as an API key.

## Run
Use the included `frontend/package-lock.json` with the matching package.json versions. From `frontend`, run `npm ci`, then `npm run dev`. In a separate terminal, run the backend from `backend` with `python -m uvicorn app.main:app --reload --port 8000`.

A live Yahoo Finance request and full frontend build still need to be verified on the target machine.

## 6. Per-user workspace isolation
- Company lists and company detail/history are filtered to the signed-in user's companies.
- Assessment history, assessment detail, reports, batch downloads, dashboard counts/charts/recent items, and assistant context are filtered to the signed-in user's assessments.
- Assessment creation and batch processing reject company IDs outside the signed-in user's workspace.
- Notifications generated by assessments and batch jobs are assigned to that user and notifications/read-all are user-scoped.
- Yahoo Finance assessments reuse/create companies only within the signed-in user's workspace, preventing shared company records from exposing another user's history.

## 7. Assessment deletion
- Added `DELETE /api/assessments/{aid}` with ownership validation.
- Added a Delete action to Assessment History with a confirmation prompt.
- The history and dashboard queries refresh after deletion.

## 8. Assistant reliability
- The chat UI now safely handles missing/empty assistant replies and shows a readable error instead of rendering an empty response.
- The send button is explicitly `type="button"`, and Enter sends without triggering any form navigation.
- The backend returns a helpful fallback response if the assistant/provider unexpectedly fails.

## Verification
- Backend `app/main.py` passes Python bytecode compilation (`python -m py_compile app/main.py`).
- The complete frontend build has not been run in this packaging environment because frontend npm dependencies are not installed here; run `npm ci` and `npm run build` locally to verify the target machine's environment.


## 9. Automatic daily market and financial monitoring
- Added Yahoo Finance daily market-history capture: source date, latest/previous close, daily return, five-trading-day return, volume, and 20-trading-day annualized volatility.
- Monitoring snapshots now include market observations alongside latest available company financial statements; source changes are compared and recorded.
- Fundamental statement/model-input changes trigger a fresh XGBoost assessment. Daily price changes update a separate transparent market-stress signal; escalating high/critical market stress creates a notification.
- Monitoring list and history API expose market metrics and market signal; the Monitoring UI shows the market metrics separately from fundamental credit-risk probability.
- Scheduler performs a pass at startup and every 24 hours while the backend process remains awake. For production reliability on sleeping/restarting hosts, an external persistent scheduler is still required.
- Important model limitation: current XGBoost was trained on annual Polish bankruptcy ratios, not daily market features, so stock returns are not falsely fed into the model as if it were trained/calibrated for them. A future model that directly predicts credit risk from market prices requires suitable labelled training data.
- Validation performed: Python compilation passed for `backend/app/main.py` and `backend/app/yahoo_finance.py`; mocked market-history extraction and market-signal rule checks passed. Full frontend build remains to be run with `npm ci` and `npm run build` on a machine with npm dependencies installed.
